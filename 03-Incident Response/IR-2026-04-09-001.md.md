# INCIDENT REPORT — WAN Connectivity Failure (pfSense VM)

## Classification

- Type: Infrastructure / Network
- Severity: Medium
- Impact: Loss of WAN connectivity
- Root Cause: Virtual NIC + NAT instability
## Incident ID

IR-2026-04-09-001

---

## Summary

A WAN connectivity failure was observed on the pfSense VM within the SOC_SECURE homelab. The issue resulted in loss of outbound internet access for both pfSense and downstream clients (Kali VM).

The root cause was identified as a combination of virtual NIC incompatibility and hardware offloading issues within a VirtualBox environment.

---

## Environment

- Platform: VirtualBox
    
- Firewall: pfSense 2.7.0 (FreeBSD)
    
- Network Design:
    
    - WAN: VirtualBox NAT
        
    - LAN: Internal Network (`labnet`)
        
- Affected Systems:
    
    - pfSense VM
        
    - Kali Linux VM

## Root Cause

### 1. Virtual NIC Offloading (FreeBSD limitation)

Hardware offloading features caused packet corruption in the virtualized environment:

- Checksum offloading
    
- TCP segmentation offloading
    
- Large receive offloading
    

---

### 2. virtio-net Instability

Use of:

```text
Paravirtualized Network (virtio-net)
```

led to:

- inconsistent packet handling
    
- unreliable NAT communication
    

---

### 3. VirtualBox NAT Binding Issue

- NAT interface appeared correctly configured
    
- but actual forwarding path was broken
    
- required manual reset
    

---

## Remediation Actions

### Action 1 — Change NIC Type

```text
virtio-net → Intel PRO/1000 MT Desktop (82540EM)
```

Applied to WAN and LAN interfaces.

---

### Action 2 — Reset Virtual NIC Binding

Procedure:

1. Set adapter to "Not attached"
    
2. Apply
    
3. Reassign to "NAT"
    
4. Apply
    

---

### Action 3 — Disable Hardware Offloading

pfSense path:

```text
System → Advanced → Networking
```

Disabled:

- Hardware Checksum Offloading
    
- TCP Segmentation Offloading
    
- Large Receive Offloading
    

---

### Action 4 — Reconfigure WAN DHCP

```text
Configure IPv4 via DHCP → YES
Configure IPv6 via DHCP6 → NO
```

---

### Action 5 — Manual DHCP Recovery

```bash
dhclient em0
```

## Lessons Learned

- Virtual NIC offloading must be disabled in pfSense VMs
    
- Intel emulated NICs are more stable than virtio in VirtualBox
    
- VirtualBox NAT can fail silently despite valid configuration
    
- Always validate connectivity layer-by-layer:
    
    - Interface
        
    - Gateway
        
    - Internet
        
- Intermittent failures often indicate virtualization issues, not firewall rules
